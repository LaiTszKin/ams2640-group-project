## Verification

- **Flow**: F11 交付
- **Covers**: `T13`（模型閘 `G1` 之後）
- **Shape**: `A modelling` — 判定表轉成可證偽性質，含每個拒絕分支與負向控制
- **Files owned**:
  - `tests/testthat/test-11_F11.R` — 性質與斷言
  - `tests/testthat/harness-11.R` — 本流程的預算、執行上限與入口；樣本、種子、暫存與輸出根一律取自 `helper-harness.R`
  - `tests/testthat/pins/11_F11.md` — 反例的 trace、seed、最短序列
- **Steps**:
  1. 讀已落地的 seam，逐條抄出判定表（輸入、前置、結果、拒絕類別、後置）
  2. 為每條性質寫斷言，含上列的拒絕分支；退化 fixture 一律在 `harness_dir()` 的暫存副本上造，不改 `output/`、不改 `programs/`
  3. 以測試台取得樣本、種子與暫存；執行，失敗時收縮並記下最短序列
  4. 把反例寫入 `pins/`；另指名一條被改錯的斷言做負向控制，確認測試會紅
  5. 報告附 trace、seed、收縮步數與負向控制的紅燈輸出
- **Properties（每條可證偽，含拒絕分支與負向控制）**:
  - 單一入口以子程序執行全部分析，結束碼為 0，記錄含每步耗時與套件版本
  - `number_map.csv` 為 28 列，逐列覆蓋 spec 的每個 `number_key`，且每列帶 `population` 與 `n`
  - 任一分析表缺母體或 n 時以 `refuse:missing-profile` 停止，且 `number_map.csv` 不落地（以暫存輸出根斷言無此檔）
  - spec 列數改為 27 時以 `refuse:incomplete-spec` 停止（負向控制）
  - 兩次執行的逐檔 sha256 比較交由 `V14` 判定（A-8／A-9），本任務只斷言交付行為：28 列覆蓋、母體與 n 齊備、拒絕分支
- **Budget**: 樣本：3,630 與 2,828 各全列一次；無抽樣；種子 20261117（由 `helper-harness.R` 提供）；收縮上界 200 次且 30 秒；單流程上限 600 秒；重試 0 次；種子與收縮在無隨機來源的流程上記 `n/a`

## Report format

完成後回報四項，缺一即視為未完成：

1. **Result** — construction：呼叫者現在看到什麼；verification A：走到哪些分支、用了多少預算、抓到什麼（trace、seed、最短序列）與**負向控制**的紅燈輸出；C：變更前後的通過與否、違規清單、門檻值與實測值（含掃描檔數）。
2. **實際建立或修改的檔案**，逐項對照 `Owned files`。
3. **偏離本檔之處與原因**；沒有則寫 `none`。
4. **在 owned files 內無法交付的部分**與其所需決定；verification 另附發現的生產缺陷與其 seam。
