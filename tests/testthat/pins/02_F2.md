## 1. 反例：`withr::with_dir()` 的回呼形式沒有執行子行程

- **最短序列**（1 步）：`withr::with_dir(root, function() system2(...))`。
- **trace**：`f2_run()` 於 `as.character(output)` 停下
  `Error in as.character(output): cannot coerce type 'closure' to vector of type 'character'`；
  `class(o)` 為 `function`，子行程根本沒跑。
- **成因**：withr 3.0.3 的實作為 `with_dir(new, code) { old <- setwd(new); on.exit(setwd(old)); force(code) }`；
  `force()` 只求值一次**表達式**，傳入 `function() {...}` 得到的是函式物件本身。
- **修正**：改傳大括號表達式 `withr::with_dir(root, { ... })`，並在 `f2_run()` 就地留一行註解。
- **同時警告**：`pdd/V03` 的 `harness-03.R` 的 `f3_run()` 用的是同一個回呼形式，會踩同一個坑
  （不屬本任務 owned files，未動）。

## 2. 反例：注入路徑未正規化 → `refuse:readonly-target` 判定落空

- **最短序列**（2 步）：`f2_run(fixture, dirname(fixture))`，其中 `fixture` 為
  `harness_data("full", ...)` 寫在 `harness_dir()` 的副本，`out_root` 以 `dirname()` 的字面值傳入。
- **trace**：結束碼 0（`attr(output, "status")` 為 `NULL`），輸出為
  `01_prep_data: 母體 full=4424 analysis=3630 ability=2828` 與
  `清冊 .../dir-f0c124bf7baa/tables/population_ledger.csv（9 列）`——拒絕沒有發生，
  清冊與記錄落在原始資料副本的目錄內；同一次執行走到底，覆寫了 `data/processed/` 三個產物
  （`git status` 三檔 modified，內容一致但 `ams2640_clean.csv` 的欄位格式不同，2159 行差異）。
- **成因**：`01_prep_data.R` 的 `is_inside()` 以 `normalizePath(mustWork = FALSE)` 比較字串；
  macOS 的 `TMPDIR` 是 `/var/folders/...`（符號連結到 `/private/var/...`）。原始副本存在，
  解析後成 `/private/var/...`；寫入目標 `.../tables/population_ledger.csv` 尚不存在，
  留在 `/var/...`。兩邊拼法不同，`startsWith()` 落空。
- **處置**：測試端不靠拼法取得綠燈——`f2_run()` 把 `out_root` 與 `raw_path` 都先
  `normalizePath(..., mustWork = TRUE)` 再注入。修正後同一條注入得
  `refuse:readonly-target`、副本 sha256 不變、目錄無殘留（含 `00_setup.log` 的交棒記錄已被撤回）。
- **復原**：`git checkout -- data/processed`（基線 sha256：clean `e4ded1ee…41646`、
  sas7bdat `790986ad…4a0de`、xpt `339c5feb…02641`）。測試檔另加一條收尾斷言
  （`f2_processed_shas()` 與開跑前相同），任何一次注入若走到底就會紅，不會靜默覆寫。
- **留下的生產風險**（seam：`programs/R/01_prep_data.R` 的 `is_inside()`／第 166 行）：
  判定對「輸出根的拼法」敏感。預設路徑（`PROJ_ROOT/output` 與 `data/raw` 都不經符號連結）
  不受影響，故今日不紅；但若 `RTOOLKIT_OUT_ROOT` 以符號連結或未解析的相對路徑指進原始資料
  目錄，`refuse:readonly-target` 會漏判，且該次執行會寫出全部產物。修法是把目錄與目標
  都對「最長的既有前綴」解析後再比，或改用 `fs::path_real()`/`normalizePath(mustWork = TRUE)`
  於父目錄。**本任務不改生產檔案**，記於此交主代理裁決。

## 5. 拒絕的後置不只看「有沒有寫檔」（A-48 待補的兩條，已補）

A-48 的教訓是：`refuse:readonly-target` 的驗收若只驗「有沒有產出檔案」，會漏掉建目錄、
寫暫存、改權限位這一類殘留。原來的注入是「輸出根＝副本目錄本身」，兩條測不到的路徑
因此沒有斷言：**輸出根是 raw 下尚未存在的子目錄**（改前由 `dir.create(recursive = TRUE)`
建出來）與**輸出根經符號連結指進 raw**（字串判定會落空）。

**新增的兩條斷言**（`test-02_F2.R`，第 6 節）：

1. `out_root = file.path(raw_dir, "sub")` → 結束碼非 0、`refuse:readonly-target`、
   `expect_false(dir.exists(file.path(raw_dir, "sub")))`、raw 目錄列舉（`all.files = TRUE`）與
   執行前逐行相同。起點另釘一條 `expect_false(dir.exists(target))`，否則後面的
   `expect_false()` 恆假、這條注入證明不了任何事。
2. `link → raw_dir`（連結放在另一個 `harness_dir()` 裡），`out_root = file.path(link, "tables")`
   → 結束碼非 0、拒絕訊息指名**實體**路徑、`sort(list.files(raw_dir, all.files = TRUE))`
   與執行前逐行相同。另以 `expect_true(file.symlink(...))` 確認連結真的建立成功。

**入口的一處必要放寬**：`f2_run()` 原本要求 `out_root` 已存在（`dir.exists()` +
`normalizePath(mustWork = TRUE)`），而這兩條注入的輸出根正是「尚不存在」的那個目標。
故加 `allow_absent_out_root = FALSE` 參數（預設行為不變）：設 `TRUE` 時原樣注入字面路徑，
**不代為建立、也不代為解連結**——建立就是被測的副作用本身；在測試端解開連結則等於替生產端
做了判定，第二條會退化成第一條。

**證偽**：把 §0 的 `refuse_readonly()` 移回 `source("programs/R/00_setup.R")` 之後（暫存副本
`/tmp/v02b_old`，只動那一處，`programs/` 的其餘與 owned 檔同步複製），以同一條
`test_file()` 執行。兩條新斷言都轉紅，紅燈原文：
