## 4. 拒絕分支的後置：number_map.csv 不落地

寫檔是 `f11_deliver()` 的**最後一步**，故拒絕分支下連開檔都不會發生——不是「先寫再刪」。
三種驗法都做：

| 驗法 | 實測 |
| --- | --- |
| 乾淨暫存根 ＋ `refuse:incomplete-spec` | `number_map.csv` 不存在（27 列與 29 列各一次） |
| 乾淨暫存根 ＋ `refuse:missing-profile` | `number_map.csv` 不存在，且 `tables/` 目錄仍為空（0 個檔） |
| 已有 `number_map.csv` ＋ 拒絕 | 檔案的**逐位元組**不變（以 `readBin()` 比對哨兵內容） |

哨兵內容：`number_key,spec_value\ndo_not_touch,0\n`。第三次驗法是為了擋住「拒絕時把
既有交付物刪掉或覆寫」這一類修法——那同樣讓報告失去來源。

## 8. 需要 T13 裁決的三件事（本模型已表態，但改了就會紅）

模型的列鍵讀法是 `H11_ROW_KEY_COLUMNS`：把指名的欄以 `|` 相接。理由是單欄不足以指名
一列：`model_comparison` 是**六列五個模型**（`model` 只有五個不同值）、`macro_values`
是**三十列三個變數**、`age_tests` 是**兩個檢定**（`test` 只有兩個值）。若 T13 用別的
寫法（例如 `a_25_29` 一類短名，A-41 的 `row_key` 就是這樣），P8 會以
`refuse:missing-profile` 指名「source_row 在表中找不到」，而不是靜默錯位。

| 表 | 缺口 | 本模型的處置 |
| --- | --- | --- |
| `age_tests` | `number_map.csv` 只有一個 `n` 欄，該表的 n 是 `n_a`／`n_b` | 拒絕，訊息指名兩欄；不自行挑一個 |
| `macro_values` | 一個 `variable` 對多個年度；`source_row` 須含 `year` | 列鍵取 `variable|year` |
| `number_map.csv` 的 `table_value` | spec 只有 `source_table`＋`source_row`，**沒有欄名**，取值規則未定 | 以 `resolve` 注入；未注入時 `table_value` 與 `pass` 皆 `NA`，不記成 `TRUE` |

`pass` 的第三點是「報告引用的數字在表中找不到」那條 must-never 的落地面：解析不到就
是 `NA`，不是通過。P9 三個方向都釘住（無解析器 → 全 `NA`；整列偏移 1 → 全 `FALSE`；
同值 → 全 `TRUE`）。
