## 3. 反例與「最短序列」

| 反例 | 最短序列（單一突變） | 觀察 |
| --- | --- | --- |
| 年份錯位（同欄） | `f8_swap_years(tbl, 1, 2)`：`Unemployment rate` 的 2008 ↔ 2009 兩列互換 year | 違反 **4** 條：`2009` 的 value 7.6（契約 9.4）、`2009` 的 n 452（契約 424）、`2008` 的 value 9.4（契約 7.6）、`2008` 的 n 424（契約 452） |
| 年份錯位（跨欄） | `f8_swap_years(tbl, 1, 13)`：`Unemployment 2008` ↔ `Inflation 2009` | 違反 **6** 條：兩欄各出現重複年份（2010／2008），另有 4 條值與 n 的錯位 |
| 1.4 的合計當成單列 | 期望 435 而非 726 | 紅：`726 - 435 == 291`（正是漏掉的那一列） |
| 不同值數由 9 讀成 10 | 把 `Inflation rate` 的兩列 1.4 併成一列 | 表長 29、`(variable, year)` 網格缺一列，且 1.4 的 n 合計仍是 726 → 兩條同時紅 |

**為什麼「互換兩列 year」是這條性質的最短反例**：互換之後表長仍是 30、每欄仍 10 列、
`(variable, year)` 仍唯一、每年度的網格仍完整、每欄 n 合計仍是 3,630、不同值數仍是
10／9／10、每個 value 的 n 合計也沒動（n 跟著列走，不跟著年份走）。**唯一壞掉的是
「年份 ↔ 值 ↔ 人數」的綁定**，正是 P3 要釘的東西。

**收縮**：本流程沒有隨機來源；失敗輸入的空間是「30 列任取兩列」的有限集合，最小反例
是相鄰同欄的兩列（4 條違反，已是單一突變能造成的最小集合）。故收縮步數記 0、最短序列
即上表的 `f8_swap_years(tbl, 1, 2)`。**種子** n/a 同理。
