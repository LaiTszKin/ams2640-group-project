## 3. 反事實：切法被釘住

同一批 2,828 人、同一欄，改用 `quantile()` 的四分位切點（type 7）分組，人數為
**707／739／680／702**（切點 10.000000、11.885417、12.833333、13.800000、18.571429）——
與本表的 707×4 不符。測試同時要求兩件事：表等於等量切組的重算，且不等於分位數切點法的
重算；只驗前者無法區分「切法正確」與「切法被換掉但剛好同寬」。

含零分者的同一切法（分析母體 3,630，等量切組 907／907／907／909）首尾差為
**77.8655 個百分點**（四位有效數字 77.87），與本表的 37.4823 相差 40 個百分點以上；
測試以「相差 ≥ 40」為斷言，避免把 PRD 記載的 77.96 當成釘值（見 §6）。

## 4. 拒絕分支：剔除後母體為零

最短序列（5 步，無可再縮）：

1. `harness_data("full")` 取 4,424 列，把第二學期成績欄整欄設為 0，寫成清洗資料集形狀的
   fixture（`harness_dir()` 內，非專案目錄）。
2. 把 `programs/R/04_ability.R` 複製到 `harness_dir()`，**只改** `CLEAN_PATH` 那一行
   （seam 必須恰好出現一次，否則停手）。生產檔不動。
3. `harness_out_root()` 取空的輸出根，先把已發佈的兩張表複製進去 → 兩份副本的 sha256
   即上表的值（前置條件，測試先驗）。
4. 在獨立環境 `sys.source()` 注入後的副本：`refuse:empty-denominator`，
   訊息為「剔除零成績後母體為 0 人，不足以等量切成 4 組（分析母體 3630 人、其中第二學期
   零分 3630 人）」。耗時 0.6–0.8 秒。
5. 重取兩份副本的 sha256：與第 3 步相同；專案 `output/tables/` 的兩個值亦不變。
   即拒絕是「不寫表」，不是「寫一張空表」。

負向控制（同一支注入、只換輸入）：把 `CLEAN_PATH` 指向真實的清洗資料集，同一份腳本
成功結束，且寫出的兩張表與已發佈的逐位元組相同——證明拒絕來自 fixture，不是注入本身壞掉。

## 5. 負向控制實錄（測試會紅）

分位表換成 quantile() 切點法的 707/739/680/702、q2→q2 由 285 改為 209、刪掉 missing_sem1
列、q4 列一格 +1 同列另一格 −1（20 格合計不變、只壞欄邊際）、population 由 ability 改為

## 6. 交付時發現、但不自行改寫的三處

1. **`04_ability.R` 缺輸入覆寫**：`02_wealth.R` 與 `08_audit.R` 都以 `RTOOLKIT_CLEAN_PATH`
   指向注入副本，`04_ability.R` 沒有；本流程的退化 fixture 因此改為「複製腳本、只改
   `CLEAN_PATH` 一行」。seam 為第 28 行的 `CLEAN_PATH <- file.path(PROJ_ROOT, ...)`。
   若生產端補上 `RTOOLKIT_CLEAN_PATH`，`h05_injected_script()` 可退回單獨設環境變數。
2. **`AMENDMENTS.md` A-8 的「V05 釘 5×5」與落地形狀不符**：移動表的 20 個計數格是
   5 列 × 4 欄（5×5 會把 `n` 欄算成一格，或假設存在第五個計數欄）。本流程依任務檔
   `V05-F5-能力層-的模型.md` 的「5 列 × 4 欄共 20 格」與「欄邊際 707」釘住，並另釘
   `n` 欄＝四個計數欄的列合計。請主代理裁決以何者為準。
3. **PRD F5／D4 的 77.96 不可由本切法重現**：含零分者的等量切組首尾差實算 77.8655
   （四位有效數字 77.87），quantile() 切點法為 78.6550。兩者都不是 77.96。測試因此只釘
   本表的 37.4823 與「相差 ≥ 40 個百分點」，不把 77.96 當釘值；報告的寫法請主代理裁決。
4. **`test-04_F4.R` 在 `test_dir()` 下 3 個 error（不是本流程的檔，未改）**：該檔第 23 行
   `source(found[[1L]])` 把 `h04_*` 放進 globalenv，其註解假設「測試環境的父環境即
   globalenv」。testthat 3.3.2 的 helper 是載進**測試 env**（globalenv 的子 env），故
   globalenv 的 closure 看不到 `harness_data()`／`harness_dir()`／`harness_out_root()`；
   `tests/testthat.R` 全綠只是因為那個入口先把 helper 源進 globalenv。修法與本流程同形：
   `source(..., local = environment())`（照 `test-03_F3.R` 第 25 行），或讓 `harness-04.R`
   在載入時自行載台。

## 7. 入口一致性：本流程的修正與驗證

**症狀**：`Rscript -e 'testthat::test_dir("tests/testthat")'` 下 `test-05_F5.R:114`、`:151`
判紅，`Rscript tests/testthat.R` 全綠。

**成因**：`harness-05.R` 原本只在 `h05_entry()` 內用 `exists("harness_table")` 判斷後才
`source("helper-harness.R")`。那個時機只在入口被呼叫時才到；`test_dir()` 直接跑測試檔時
`h05_published_paths()` 先呼叫 `.harness_table_path()`，於是紅在「函式不存在」。

**修法**：`harness-05.R` 新增第 0 節，在**載入時**（top-level，不在任何函式內）
`source(file.path(h05_this_dir(), "helper-harness.R"), local = TRUE)`，載進「本檔被求值的
同一個環境」＝`h05_*` 的 closure 所在處。另把 `h05_this_dir()` 的解析順序改為
「source 堆疊上指向 `harness-05.R` 的 ofile → `--file=harness-05.R` → 工作目錄」：
原本先看 `--file=`，在 `tests/testthat.R` 之下會把目錄誤判成 `tests`。

**驗證**（工作樹 `pdd/V05b`；F5 段落兩種入口皆 9 個 test_that、55 條斷言、0 failed 0 error）：
